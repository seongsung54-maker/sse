# PageSpeed Insights로 전후 확인하기
목적은 느림의 원인을 확인하고 학생의 메킷애센 작업본으로 해결 가능한 항목을 개선하는 것이다. 점수 100점이나 승인·순위 상승을 약속하지 않는다. 이 수업의 검사 기능은 속도 측정기가 아니다.

## 먼저 받을 자료
학생이 개선하려는 글의 정확한 URL, 모바일/데스크톱 구분, 측정 시각, PSI 결과 링크·캡처·보고서를 확인한다. URL만 받고 이미 측정했다고 말하지 않는다. 주소에 토큰·개인정보가 있으면 공개 측정 서비스로 보내지 않는다.
PageSpeed Insights는 Google 쪽에서 접근할 수 있는 페이지를 측정한다. localhost·로그인 전용 연습 환경은 공개 서비스 측정 대상으로 삼지 않는다. 가능한 경우 로컬 Lighthouse로 따로 측정하고 그 결과를 PSI 결과와 섞지 않는다. 도구 설치나 연습 사이트 공개가 필요하면 확인 없이 실행하지 않는다.

## 기록
- 모의 검사(Lighthouse): 성능 점수, LCP(큰 내용 표시 시간), CLS(배치 흔들림), TBT(모의 검사 중 작업 차단 시간)를 보고서에 있을 때 기록.
- 실제 방문자(CrUX): URL/사이트 전체 범위와 집계 기간, LCP·INP·CLS, 데이터 없음 여부를 별도 기록. TBT를 실제 사용자 INP로 바꿔 부르지 않음.
- 변경 전후 같은 URL·기기 조건·콘텐츠·광고·캐시 조건으로 측정한다. 모의 결과는 가능한 경우 각 3회 측정해 중앙값과 변동 폭을 함께 남긴다. 3회는 수업의 비교 절차이지 Google의 의무 조건이 아님.
- CrUX는 최근 28일 집계이므로 방금 수정한 효과를 즉시 증명하는 자료로 쓰지 않는다. 데이터 없음은 0점이 아니다.

## 원인을 나누고 한 가지 수정
보고서의 항목과 실제 네트워크 자원·소스를 연결한다. 플러그인 / 테마 / 이미지 파일 / 호스팅 / 캐시 / 광고·외부 스크립트의 담당을 구분한다.
플러그인 개선 후보는 실제 증거가 있을 때만 선택한다: 필요 없는 페이지에서의 CSS·JS 로딩, 잘못된 이미지 크기 선택, 이미지 공간 미확보, 불필요한 중복 처리 등.
첫 화면의 주요 이미지를 무조건 지연 로딩하지 않는다. 자바스크립트를 일괄 지연하거나 다른 플러그인의 자원을 삭제하지 않는다. 서버 응답 지연을 CSS 수정으로 해결했다고 하지 않는다. 광고·동의·통계·라이선스 기능을 제거해 좋은 점수만 만들지 않는다.

## 다시 확인
동일 조건의 수치와 함께 화면·메뉴·링크·관련 글·이미지·기존 검색 출력을 재검사한다. 결과는 개선/차이 불명확/악화/미측정으로 구분하고, 지표끼리 상충하면 함께 보고한다. 사이트 공개나 운영 적용은 별도 권한과 복구 확인이 필요하다. 공개 PSI에 접근하려고 연습 환경의 noindex·보호 설정을 무단 해제하지 않는다.
