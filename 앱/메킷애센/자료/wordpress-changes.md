# 플러그인 변경
## 먼저 출력 경로
플러그인 헤더, 훅 등록, 렌더러, 관련 CSS·JS, 저장 옵션을 확인한다. 템플릿·본문 저장 HTML·런타임 필터 중 실제 화면 소유자를 찾는다.
파일·함수 이름은 버전에 따라 바뀐다. 과거 줄 번호나 예제 클래스가 항상 존재한다고 가정하지 않는다.

## 수정판 또는 추가 플러그인
기존 렌더러 내부 변경이면 작업본 수정이 적합하다. 새 기능이며 공개 훅으로 연결 가능하면 독립 플러그인을 고려한다.
폴더 이름 변경만으로 동시 활성화가 안전해지지 않는다. 함수·클래스·상수·옵션·자산 핸들·업데이트 식별자를 검사한다.
교체형 수정판은 원본과 동시 활성화하지 않는다. 기존 옵션 키를 무작정 바꾸면 설정이 사라진 것처럼 보일 수 있다.
외부 유료 플러그인 권한·라이선스 확인을 우회하지 않는다.

## 구현 기준
- 기존 최소 PHP·WordPress 지원 범위를 먼저 읽는다. 큰 프레임워크·Composer·최신 문법을 자동 도입하지 않는다.
- DB 변경 없는 요청에는 DB 마이그레이션·초기화·콘텐츠 재생성을 넣지 않는다.
- 입력 검증·권한·nonce·출력 문맥별 escaping을 구현한다. nonce는 권한 검사를 대신하지 않는다.
- 조회는 공개 글·의도한 유형·개수·정렬을 명시. 비공개·임시·비밀번호 글 노출을 검토.
- 이미지가 없거나 관련 글이 없는 경우, 긴 제목과 모바일, 키보드 포커스를 확인.
- 스타일은 좁은 클래스 범위로 제한. 본문 전체를 정규식으로 교체하거나 관련 없는 훅을 제거하지 않는다.
- 외부 이미지·폰트·분석 요청을 몰래 추가하지 않는다. 기존 수익화·측정 코드를 임의 제거하지 않는다.
