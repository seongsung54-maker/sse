# Codex 내부 작업 규칙

이 폴더는 월부 중급반 애드센스 승인글 자동화의 프로그램 폴더다.

## 절대 규칙
- 이 프로젝트 폴더와 그 하위 밖으로 절대 나가지 않는다. 상위 폴더, 형제 폴더, 다른 프로젝트 복사본, 비슷한 이름의 폴더는 읽지도, 검색하지도, 수정하지도 않는다.
- 파일을 찾을 때 `find`, `grep`, `ls` 같은 검색을 프로젝트 폴더 밖에서 실행하지 않는다. 파일이 안 보이면 다른 폴더를 뒤지지 말고 사용자에게 현재 폴더 기준으로 다시 확인만 요청한다.
- `.env.local`은 오직 이 폴더의 `./.env.local` 한 곳에만 존재한다. Codex는 이 파일을 직접 만들거나 수정하지 않는다 — 값 입력은 `키설정`(npm run keys) 스크립트가 담당한다. 다른 경로에 `.env.local`을 절대 만들지 않는다.
- 새 날짜 폴더, 새 프로젝트폴더, 비슷한 이름의 폴더를 만들지 않는다.
- 경로가 헷갈리면 먼저 `pwd`와 `ls`로 현재 위치를 확인한다. 그래도 헷갈리면 작업을 멈추고 사용자에게 알린다. 다른 폴더로 이동해서 계속하지 않는다.
- 현재 작업 기준 폴더는 이 `99_절대_건들지마세요_프로그램파일` 폴더다.
- 비밀번호, 애플리케이션 비밀번호, OpenAI API 키는 답변에 다시 출력하지 않는다.
- 워드프레스 글은 공개 발행하지 말고 임시글로만 저장한다.
- 승인글 본문, SEO 키워드, 카테고리를 코덱스가 직접 만들지 않는다. 글 생성은 반드시 `scripts/adsense-create-drafts.mjs` 또는 `scripts/adsense-auto-drafts.mjs` 실행으로만 처리한다.
- 제목은 수강생이 준 것과 제목 파일에 있는 것만 사용한다. 코덱스가 임의로 제목을 만들어 발행하지 않는다.
- 코덱스의 역할은 스크립트 실행과 결과 확인, 쉬운 말 안내까지다. 글 내용에 개입하지 않는다.

## 정확한 파일 위치
- 환경설정 파일: `./.env.local`
- 환경설정 예시: `./.env.example`
- 워드프레스 연결 확인: `node scripts/wordpress-connection-check.mjs`
- 사이트 자동 매핑 임시글 생성: `node scripts/adsense-auto-drafts.mjs --limit=10`
- 사이트 지정 임시글 생성: `node scripts/adsense-create-drafts.mjs --site=1`
사이트는 1번부터 10번까지 있다. N번 사이트는 전부 같은 규칙을 따른다.

- 사이트N 제목 파일: `../애드센스 승인글/01_제목넣는곳/사이트N제목.txt`
- 연결정보: `ADSENSE_SITE_NN_*` (NN 은 두 자리 — 01, 02, … 10)
- 실행: `--site=N` → 결과 폴더 `site-NN`

예: 사이트7 → `사이트7제목.txt` / `ADSENSE_SITE_07_*` / `--site=7` / `site-07`
- 생성 결과 확인 폴더: `../애드센스 승인글/02_생성결과_확인용`

## 제목 파일 자동 매핑 절대 규칙
- 제목을 찾아서 발행하라는 요청은 반드시 `../애드센스 승인글/01_제목넣는곳` 폴더를 먼저 확인한다.
- `makeit-adsense/inputs/site-01/titles.txt` 같은 내부 예비 파일을 우선 사용하지 않는다.
- 사이트N 은 `사이트N제목.txt` 만 사용한다. 사이트1 제목을 사이트10 에 올리면 안 된다.
- 사이트 번호가 명확하면 해당 사이트만 실행한다. 예: `사이트2 글 10개` → `node scripts/adsense-create-drafts.mjs --site=2 --limit=10`
- 사이트 번호가 없고 "알아서", "추가로", "제목 찾아서"처럼 말하면 `node scripts/adsense-auto-drafts.mjs --limit=10`을 실행한다.
- 자동 매핑 스크립트는 사이트1~10 제목 파일과 `ADSENSE_SITE_01`~`ADSENSE_SITE_10` 연결정보를 확인하고, 둘 다 준비된 사이트만 실행한다.
- 여러 사이트가 준비되어 있으면 각 사이트의 제목 파일을 각 사이트에 맞춰 순서대로 임시글을 만든다. 다른 사이트의 제목을 섞으면 안 된다.

## .env.local 변수명
아래 변수명만 사용한다. 다른 이름을 새로 만들지 않는다.

- `OPENAI_API_KEY`
- `ADSENSE_SITE_01_URL` / `_USER` / `_APP_PASSWORD`
- … 같은 규칙으로 `ADSENSE_SITE_10_*` 까지 (쓰는 만큼만 채워진다)

`SITE1_DOMAIN`, `SITE1_ADMIN_ID`, `SITE1_APP_PASSWORD`, `WORDPRESS_DOMAIN` 같은 새 변수명은 만들지 않는다.

## 자동화 시작 흐름 (수강생 첫 명령 — 가장 중요)
사용자의 요청에 "애드센스", "자동화", "승인글" 중 하나라도 들어 있고 아직 설정이 안 된 상태면 (예: "애드센스 자동화 시작해줘", "애드센스 승인글 자동으로 해줘"), 아래 순서를 그대로 따른다. 순서를 건너뛰거나 바꾸지 않는다.

> **시크릿 단일 정책 (루트 AGENTS.md와 동일 — 예외 없음)**: 키·비밀번호·연결정보는 절대 채팅으로 받지 않는다. Codex가 `.env.local`을 직접 만들거나 수정하지도 않는다. 값 입력은 오직 수강생이 터미널에서 `키설정`(npm run keys)을 실행하는 방식만 안내한다.

1. 설정 상태를 스크립트로 확인한다: `npm run doctor`. `.env.local` 파일을 직접 열지 않는다.
2. `OPENAI_API_KEY`, `ADSENSE_SITE_01_URL`, `ADSENSE_SITE_01_USER`, `ADSENSE_SITE_01_APP_PASSWORD` 중 비어 있는 값이 있으면, 값을 채팅으로 받지 말고 터미널에서 `키설정` 실행을 안내한다. 완료 후 다음으로 진행한다.
3. `node scripts/wordpress-connection-check.mjs`로 연결을 확인한다. 실패하면 어떤 항목이 문제인지 쉬운 말로 알려주고, 그 항목만 `키설정` 으로 다시 입력하게 안내한다.
4. 연결이 성공하면 `../애드센스 승인글/01_제목넣는곳/사이트1제목.txt`에 실제 제목이 있는지 확인한다. 주석(#)과 빈 줄만 있으면 "어떤 주제로 승인글 써드릴까요? 제목을 1개만 주셔도 되고, 30개나 100개처럼 여러 개를 한 줄에 하나씩 주셔도 됩니다."라고 묻고, 받은 제목을 그 파일에 한 줄에 하나씩 저장한다. (제목은 시크릿이 아니다)
5. 제목이 준비되면 `npm run doctor` 출력 맨 아래의 `상태:` 줄을 먼저 본다.
   `상태: 처음` 일 때만 "설정이 끝났어요! 테스트로 글 1개를 임시글로 발행해볼까요?"라고 묻는다.
   `상태: 이어하기` 면 이 단계를 건너뛰고, 진행 상황을 알려준 뒤 개수만 묻는다.
6. 사용자가 동의하면 `node scripts/adsense-create-drafts.mjs --site=1 --limit=1`을 실행하고, 성공/실패와 워드프레스 관리자 화면에서 임시글을 확인하는 방법을 짧게 알려준다.
   **돈 보고는 생략 금지.** 스크립트가 글마다 찍는 `💰` 두 줄(이 글 토큰·원·충전액 대비 %, 지금까지 쓴 돈, 남은 돈)과 마지막 배너의 `💰` 줄은 요약하지 말고 숫자 그대로 사용자에게 전달한다. 남은 돈이 안 나오면 "'키설정'에서 충전한 금액을 넣으면 남은 돈도 보여 드려요"라고 한 줄 덧붙인다.
   진행 게이지 `[■■■□□□] 30% │ 3/10번째 글 │ …` 줄은 실행 중 사용자가 볼 수 있게 두고, 완료 후 보고에는 넣지 않는다.
7. 테스트 1개가 성공하면 개수만 안내한다: "이제 한 번에 몇 개씩 만들지 말씀해 주세요. 예: '10개 만들어줘'" — 날짜는 먼저 물어보지 않는다.
8. 이후 개수는 `--limit=숫자`, 날짜는 아래 '발행 날짜 설정'을 따른다.

## 발행 날짜·시간

**정해진 규칙은 없다.** 하루에 1개를 올리든 100개를 올리든 사용자 마음이다.
프로그램은 개수도 간격도 강요하지 않는다. 아래는 전부 ‘사용자가 요청했을 때만’ 붙이는 옵션이다.

**시간은 항상 자동으로 흩어진다.** 어느 모드든 각 글의 시각은 한국시간 07~23시
사이에서 무작위로 정해진다. "랜덤한 시간으로"라고 해도 이미 그렇게 동작한다.

| 사용자가 이렇게 말하면 | 붙이는 옵션 |
|---|---|
| (날짜 얘기 없음) | 없음 — **기본이 하루 3개 · 최소 3시간 간격 · 무작위 시각**(오늘부터, 지난 시간대 건너뜀). 발행을 누르면 그 시각에 예약 공개된다 |
| "지금 시각으로 바로" | `--date-mode=now` |
| "하루에 5개씩" | `--per-day=5` (기본 3) / "간격 6시간 이상" → `--min-gap-hours=6` |
| "오늘부터 하루에 1개씩", "1일 간격으로" | `--date-mode=future-daily` |
| "이틀씩", "3일 간격으로" | `--date-mode=future-daily --date-step=2` (또는 3) |
| "과거 날짜로 나눠서" | `--date-mode=past-daily` |
| "날짜도 무작위로 흩어서" | `--date-mode=random` (최근 30일, `--random-days` 로 조절) |
| "특정 날짜부터" | `--start-date=YYYY-MM-DD` |
| "매일 같은 시간에" | `--fixed-time=18:00` (이때만 시간이 고정된다) |
| "2시간 간격으로", "몇 시간씩 띄워서" | `--hour-gap=2` (숫자는 사용자가 말한 시간) |

`--hour-gap` 을 쓰면 글이 **앞날짜(미래)** 로 저장된다. 수강생이 평소처럼 '발행' 을 눌러도
워드프레스가 알아서 '예약' 으로 바꿔 주므로, 글이 정한 간격으로 하나씩 공개된다.
(날짜 없이 올린 글은 발행을 누르는 순간 그 시각으로 덮어써져서 전부 같은 때 공개된다)

주의:
- 모르겠으면 추측해서 단정하지 말고 위 표를 따른다.
  "무작위 시간은 지원하지 않는다", "시간은 오후 6시로 고정되어 있다" 같은 말을 하지 않는다.
- 사용자가 날짜 얘기를 안 했으면, 결과 보고에서도 날짜 얘기를 꺼내지 않는다.
- 몇 개를 만들지는 `--limit` 으로 그대로 따른다. 하루 몇 개까지라는 제한은 없다.

## 추가 임시글 발행 흐름
사용자가 "애드센스 자동화 글 10개 추가로 발행해줘", "승인글 10개 더 만들어줘", "임시글 10개 추가해줘"처럼 말하면:

1. 먼저 `pwd`가 이 `99_절대_건들지마세요_프로그램파일` 폴더인지 확인한다.
2. `./.env.local`이 있고 `OPENAI_API_KEY`가 실제 값인지 확인한다.
3. 연결 정보가 부족하면 글 생성을 시작하지 말고, 값을 채팅으로 받지 말고 터미널에서 `키설정` 실행을 안내한다.
4. `../애드센스 승인글/01_제목넣는곳` 안의 사이트별 제목 파일을 먼저 확인한다. 사용자에게 제목 파일 경로를 다시 묻지 않는다.
5. 사용자가 사이트 번호를 말했으면 해당 사이트만 실행한다. 예: `node scripts/adsense-create-drafts.mjs --site=2 --limit=10`
6. 사이트 번호를 말하지 않았으면 `node scripts/adsense-auto-drafts.mjs --limit=10`처럼 실행해 사이트1~10 제목 파일과 연결정보를 자동 매핑한다.
7. 개수를 말하지 않으면 `--limit=1`로 임시글 1개만 테스트 생성한다.
8. 스크립트는 이전에 성공한 제목을 자동으로 건너뛰므로 같은 제목을 다시 만들지 않는다.
9. 생성 후 실행된 사이트별 `makeit-adsense/outputs/site-0N/last-run.json`과 `../애드센스 승인글/02_생성결과_확인용/site-0N/last-run.json`을 확인하고, 성공/실패 개수만 짧게 알려준다.

## 생성 결과 확인 기준
- 영문 slug가 있어야 한다.
- OpenAI 이미지 API로 만든 가로형 이미지가 대표이미지로 등록되어야 한다.
- 같은 이미지가 본문 중간에 Gutenberg `wp:image` 블록으로 한 번 들어가야 한다.
- 이미지 alt text와 캡션에 대표키워드가 자연스럽게 들어가야 한다.
- 본문에는 h1이 없어야 하고 첫 소제목은 h2여야 한다.
- 글의 세부카테고리와 상위카테고리가 함께 체크되어야 한다.
